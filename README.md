# Cashflow Forecast

Учебное приложение для прогноза денежных остатков по дням календарного месяца
и проверки решений в режиме «Что, если?».

**Демонстрационный/учебный финансовый прогноз, не банковские данные.**
Не вводите и не публикуйте реальные финансовые данные.

Требования и границы MVP зафиксированы в [SPEC.md](./SPEC.md).

## Текущее состояние

Запускаются React-клиент и Express API с локальной SQLite-базой.
На сервере реализованы миграции, валидация, единый формат ошибок и задачи
FIN-10–FIN-21: чтение месячного плана, сохранение начального остатка,
создание/изменение/удаление разовых операций и ежемесячных правил,
месячные исключения и атомарное применение эксперимента.
Есть автоматические проверки API и сохранности данных.

## Окружение и установка

Версии Node.js и npm не ограничены в манифесте проекта, строгая проверка
`engines` не включена. Конфигурация проверена на Node.js 24 и npm 11;
Node.js 24 указан в `.nvmrc` как рекомендуемая версия и используется в CI.
Для локальной работы нужна версия, совместимая с установленными зависимостями.

Проверьте `node --version` и `npm --version`, затем из корня репозитория выполните:

```sh
npm ci
npm run check
```

Если используется nvm-windows, выберите совместимую установленную версию
командой `nvm use <полная установленная версия>`. Node.js 14 не поддерживается
текущими зависимостями; снятие ограничения в манифесте не меняет их требования.

## Структура и стек

```text
apps/
  web/       React + TypeScript, Vite, Redux Toolkit / RTK Query,
             React Hook Form + Zod, Tailwind CSS
    src/     Исходники клиента
  api/       Node.js + Express, SQLite через better-sqlite3, Zod
    src/     Маршруты API, слой БД, миграции, валидация и тесты
    data/    Локальная БД (содержимое исключено из Git)
.github/
  workflows/ Проверки CI
```

TypeScript настроен в strict-режиме. Конфигурация клиента использует DOM и
модульное разрешение Bundler, сервер также использует Bundler и запуск через tsx. API-кэш планируется хранить
в RTK Query, локальный эксперимент — в Redux slices, расчёты — в чистых функциях,
согласно спецификации. Контракт API зафиксирован в `docs/API.md`.

## Команды

| Команда                | Назначение                                                           |
| ---------------------- | -------------------------------------------------------------------- |
| `npm run check`        | ESLint, проверка типов конфигурации, Vitest, проверка форматирования |
| `npm run lint`         | Проверка ESLint                                                      |
| `npm run typecheck`    | Проверка типов `vite.config.ts` и `vitest.config.ts`                 |
| `npm test`             | Запуск Vitest; отсутствие тестов пока разрешено явно                 |
| `npm run test:watch`   | Vitest в режиме наблюдения                                           |
| `npm run format`       | Форматирование Prettier                                              |
| `npm run format:check` | Проверка форматирования                                              |

`SPEC.md` исключён из автоматического форматирования, чтобы сохранить исходный документ.
CI выполняет `npm ci` и `npm run check`.
Типы исходников сервера дополнительно проверяются при `npm run build`.

Команды запуска и сборки:

| Команда                                   | Что требуется для работы                  |
| ----------------------------------------- | ----------------------------------------- |
| `npm run dev:web`                         | `apps/web/index.html` и точка входа React |
| `npm run dev:api`                         | `apps/api/src/index.ts`                   |
| `npm run build`                           | Исходники клиента и сервера               |
| `npm run start --workspace @cashflow/api` | Собранный `apps/api/dist/index.js`        |

В API локальные импорты можно писать без расширения: например, `./middleware/errorHandler`.
TypeScript использует `moduleResolution: Bundler`, а команды разработки и запуска
собранного API используют `tsx` для разрешения таких путей.

Vitest запускает проверки валидаторов, SQLite и HTTP API в окружении Node.js.
Тесты используют отдельные базы и не изменяют локальную БД приложения.

## Реализованные маршруты API

Базовый адрес по умолчанию: `http://localhost:3001/api`.

| Метод  | Путь                                     | Ответ                                                       |
| ------ | ---------------------------------------- | ----------------------------------------------------------- |
| GET    | `/health`                                | `200`, `{status}`                                           |
| GET    | `/months/:month`                         | `200`, `{month, revision, openingBalanceCents, operations}` |
| PUT    | `/months/:month/opening-balance`         | `200`, `{month, openingBalanceCents, revision}`             |
| POST   | `/transactions`                          | `201`, `{transaction, revision}`                            |
| PATCH  | `/transactions/:id`                      | `200`, `{transaction, revision}`                            |
| DELETE | `/transactions/:id`                      | `204`, без тела                                             |
| GET    | `/recurring-rules`                       | `200`, `{items}`                                            |
| POST   | `/recurring-rules`                       | `201`, `{rule, revision}`                                   |
| PATCH  | `/recurring-rules/:id`                   | `200`, `{rule, revision}`                                   |
| DELETE | `/recurring-rules/:id`                   | `204`, без тела                                             |
| PUT    | `/recurring-rules/:id/exceptions/:month` | `200`, `{exception, revision}`                              |
| DELETE | `/recurring-rules/:id/exceptions/:month` | `204`, без тела                                             |
| POST   | `/months/:month/apply-scenario`          | `200`, полный месячный план                                 |

Месячный план включает разовые операции и вхождения подходящих правил с учётом
коротких месяцев, `skip` и `override`. Чтение плана не меняет revision.
Успешные изменения остатка, операций, правил и исключений увеличивают общий revision профиля
в той же транзакции, что и запись данных. Ошибки валидации и отсутствующие
ID не изменяют данные или revision. Форматы запросов и ошибок — в `docs/API.md`.

Эксперимент отправляется полным снимком месяца с текущим revision. При конфликте
версий сервер возвращает `409 REVISION_CONFLICT`. Все изменения снимка сохраняются
в одной транзакции и увеличивают revision один раз. Регулярные правила и операции
других месяцев сохраняются; разовые изменения регулярных вхождений записываются
как исключения выбранного месяца.

## Переменные окружения

Шаблоны находятся в `apps/web/.env.example` и `apps/api/.env.example`.
При реализации скопируйте нужный шаблон в `.env` рядом с ним.
Секреты и локальные `.env` исключены из Git.

API использует `PORT=3001` и `DATABASE_PATH=./data/cashflow.sqlite` по умолчанию.
Команды запуска и создания схемы загружают `apps/api/.env`.
Относительный путь БД отсчитывается от рабочей папки процесса: при запуске
через npm workspace это `apps/api`. Можно указать абсолютный путь.
Недостающие папки создаются автоматически; пустой `DATABASE_PATH` отклоняется.

Для создания файла БД и таблиц без запуска сервера выполните из корня проекта:

```sh
npm run db:migrate --workspace @cashflow/api
```

Сервер также создаёт схему при запуске. Команду можно повторять: существующая
таблица и её записи сохраняются. Для каждого подключения явно включены внешние
ключи SQLite. Локальные файлы БД и их служебные файлы исключены из Git.

Vite настроен на порт 5173 и перенаправление `/api` на `http://localhost:3001`
при разработке. При изменении порта API потребуется изменить и адрес прокси.
Tailwind подключён как плагин Vite; импорт CSS будет добавлен с исходниками клиента.
Переменные клиента с префиксом `VITE_` публичны и не должны содержать секреты.
